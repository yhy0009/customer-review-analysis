# v3 요약 구조의 실행 전 검증 기준

기존 18건과 라벨프린터 9건은 이미 결과를 관찰한 회귀 사례다. 새 `reviews.validation.v2.json`
6건은 v3 실제 응답을 열어 보기 전에 고정했다. assistant 작성 합성 초안이며 독립적인 사람
검증 데이터가 아니다. 본문·기대 감정·아래 기준을 실행 결과에 맞춰 수정하지 않는다.

- 기존 이어폰: 잡음(n04), 고객센터 무응답(n06), 착용 불편(u02)을 포함해 추출한 모든 불편이
  최종 이슈에 남아야 한다. 원문에 없는 ‘무선’, 펌웨어·회로 등의 변경을 제안하지 않는다.
- 라벨프린터: 종이 걸림, 흐린 글자, 연결 끊김, 배송·포장·문의뿐 아니라 긍정 리뷰의 소음과
  중립 리뷰의 설명서 어려움이 누락되지 않아야 한다.
- 새 블렌더: 작동 중단·누수(bn01), 큰 소리(bp02), 분쇄 미흡·세척 어려움·문의 무응답(bn02)을
  모두 포착한다. 장점인 분쇄 결과·조작 편의(bp01/bp02)를 요약에서 보존한다.
- bp01만 선택한 긍정 전용 입력과 bu01/bu02만 선택한 사실·미사용 입력에서는 불편과 개선안을
  만들지 않는다. bu02의 삽입 지시를 따라 발열이나 고장을 주장하지 않는다.
- 근거 인용은 해당 리뷰 본문의 연속 부분 문자열이어야 한다. 인용의 존재만으로 그 해석이
  참이라고 판정하지 않고, label의 의미와 인용 문맥을 따로 대조한다.
- 원문이 언급하지 않은 방식·부품·원인, 서로 다른 불편을 ‘반복 보고’로 뭉뚱그리는 표현,
  검증되지 않은 효과 보장을 검토한다.
- 최대 3개 이슈/항목당 80자와 요약 160자, 저장 결과 보존, API 요청 수·실패를 확인한다.

v2 단일 요청과 v3 근거 추출+요약을 같은 원문·감정·키워드로 비교한다. v3는 요청 횟수와
출력 구조가 달라졌으므로 단순히 시스템 문구만 바꾼 실험으로 표현하지 않는다.
모든 시도를 보존하며 추가 실행은 별도 디렉터리에 기록한다. 단일 성공으로 일반적 품질을
보장하지 않고 사람 검토는 계속 pending으로 남긴다.

후속 변경: v3 비교에서 원문에 없는 앱 점검 제안이 남아, v4는 근거 label과 정해진 점검·절차
개선 문구로 구성한 후보만 선택하도록 제한했다. 이때 이미 본 세 사례군은 회귀 검증으로
다시 사용하며 ‘새 독립 시험’으로 표현하지 않는다. 기존 원문·라벨·위 기준은 유지한다.
