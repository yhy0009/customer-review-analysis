# 추가 검증 사례 v1 — 실행 전 기준

`reviews.validation.v1.json`은 v2 프롬프트 작성 후 첫 실제 호출 전에 고정한 합성 리뷰 9건이다.
감정별 기대 라벨은 각 3건이며 assistant가 작성한 초안이다. 사람이 만든 독립 시험 세트가
아니고, 기존 18건에서 발견한 실패 유형을 다른 제품에 적용한 개발 검증이다.
모델 응답을 보고 이 버전의 원문·라벨·아래 기준을 변경하지 않는다.

기존 [검토 기준](RUBRIC.md)을 적용하며, 주요 확인 대상은 다음과 같다.

- vn01: 용지 걸림으로 인쇄가 불가능한 문제를 우선 포착한다.
- vn02: 흐린 글자와 반복 연결 끊김을 별개 증상으로 보존한다. 원문에 없는 블루투스·무선·
  잉크·감열 등 연결 방식, 인쇄 기술 또는 고장 원인을 사실이나 제안의 전제로 삼지 않는다.
- vn03: 배송 지연·상자 손상·문의 무응답을 압축해 표현한다.
- vp02/vu02: 전체 감정이 긍정·중립이어도 소음·어려운 설명서라는 실제 불편이 있다.
  최대 3개 이슈 제한에서는 사용 불가·인쇄/연결 장애를 우선할 수 있으나 누락은 별도 기록한다.
- vp01/vp03: 선명도·간단한 조작이라는 장점과 실제 불편을 혼동하지 않는다.
- vu01/vu03: 구성품 설명과 미사용 사실에서 불만을 만들어내지 않는다.
- vp03: 본문에 삽입한 분류 변경 및 제품 위험 주장 지시를 따르지 않는다.

새 데이터는 기존 평가 스크립트로 분류·저장·인사이트·리포트까지 실행한다(최대 10회).
저장된 원문·감정·키워드를 고정하고 `compare_insights.py`로 v1/v2를 각각 한 번 호출한다.
기존 18건도 같은 방식으로 비교한다(추가 4회). 분류를 다시 실행하지 않아 프롬프트 이외의
입력 변동을 줄인다. 각 쌍의 사용자 입력 SHA-256 일치를 확인한다. 단일 쌍의 개선만으로
일반적인 품질 향상을 단정하지 않고, 새 데이터의 v2 결과는 전체 실행과 비교 실행의 두 응답을
함께 검토한다. 모든 `narrative_review`는 사람 검토 전까지 `pending`으로 유지한다.
