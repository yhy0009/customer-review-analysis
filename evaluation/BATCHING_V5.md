# v5 분할 추출 및 품질 판정 검증

2026-09-16 KST에 기존 합성 리뷰 18건과 저장된 분류를 재사용하여 라우팅 서비스의
`gpt-5-mini`를 호출했다. 감정 분석과 라벨 변경은 하지 않았다.

| 실행 | 실제 요청 | 결과 |
| --- | --- | --- |
| 최대 8건/배치 | 2회 | 첫 배치 근거 검증 통과, 두 번째 제공자 요청 실패. 부분 요약 없이 중단 |
| 최대 4건/배치 | 6회 | 근거 5회와 최종 요약 1회 모두 통과 |

첫 실행의 두 번째 요청은 약 60.25초 후 오류로 종료됐다. 기록만으로 서버 내부 원인을
단정하지 않는다. 실패 기록은 보존하고 새 출력 경로에서 4건 배치로 재실행했다.
두 실행 모두 max_retries=0이며 총 **8회 요청**이다.

성공 실행에서는 4/4/4/4/2건의 순번과 원문 인용을 검증했다. 18건의 선택 집합을 유지하고
25개 제품별 근거 주제를 반환했다. 주요 이슈는 배송 지연·고객센터 미응답·배터리 방전이며,
잡음·착용감 불편 등 선택되지 않은 불편도 전체 근거 목록에 남는다. 이는 모든 불편을
3개 문장에 압축한 결과가 아니라 리뷰 수 기준 주요 주제와 전체 근거를 함께 제공한 결과다.

근거 요청 시간은 36.80 / 34.72 / 32.44 / 46.91 / 23.04초, 요약은 18.94초였다.
한 번의 재실행 결과로 배치 크기에 따른 성능 우열이나 성공률을 확정하지 않는다.
반환된 결과로 Markdown 리포트를 생성하고 저장 통계와 대상 수·키워드가 일치하며,
25번째 주제까지 표시되는지 확인했다.

기존 평가에 예시 품질 정책을 적용했을 때 자동 지표는 충족했으나 사람 검토가
없어 `pending`/종료 코드 1을 반환했다. 예시 정책은 팀 승인 기준이 아니다.
요약 의미와 기대 라벨의 사람 검토 상태는 계속 pending이다. 분류 정확도의 신규 측정도 아니다.

자동 테스트 **335개 통과**. 100건 긴 리뷰의 분할·ID·집계 보존, 개별 요청 한도,
배치 수 사전 제한, 중간 실패·단계별 재시도, SQLite 스냅샷 해제·상태 보존, 전체 근거
리포트 출력, 정책 임계값·회귀·검토 해시·검토자 종류·CLI 종료 코드를 검증했다.

원시 성공·실패 기록, 예시 판정, 실제 리포트와 해시는
[manifest.json](results/2026-09-16/manifest.json)에 있다. 기존 평가 결과는 수정하지 않았다.
실제 실행은 기능 커밋 `4eb1384`를 사용했다. 후속 변경은 호출별 시스템 프롬프트 해시를
기록하도록 보완한 것으로, 실행 당시 프롬프트 해시는 manifest에 따로 기록했다.

```bash
python scripts/compare_insights.py --live --current-only --batch-size 4 \
  --dataset evaluation/reviews.v1.json \
  --saved-evaluation evaluation/results/2026-09-13/baseline-v1.json \
  --timeout-seconds 90 --output /tmp/cra-v5-new-run
```

위 명령은 이 고정 입력에서 최대 6회 요청하며 반드시 새 출력 경로를 사용한다.
